- 2026-10-04: Route handler functions are named by their verb (get, patch, list, create, delete), adding a short noun only when one tag has two routes with the same verb (get_file); operation IDs therefore read {tag}_{verb} or {tag}_{verb}_{noun}. Reason: they become the frontend's generated function and type names.
- 2026-10-04: Composite index on notebooks (owner_uid ascending, created_at descending) added to infra/firestore.indexes.json and data-model.md. Reason: GET /v1/notebooks filters by owner and sorts newest first; production Firestore requires this index, the emulator doesn't check.
- 2026-10-04: POST /v1/notebooks returns 201; GET /v1/notebooks puts nb_demo_6041 first on page 1 only, outside the limit, never repeated for its owner (that page may hold one fewer); next_cursor is the last notebook's ID. Reason: the demo is always one tap away, and ID cursors stay correct when new notebooks are added.
- 2026-10-04: When a handler's verb would shadow a Python builtin (list), the function gets a descriptive name (list_notebooks) and the route decorator's name= keeps the verb, so operation IDs still read {tag}_{verb}. Reason: a module-level function named list breaks list[...] type hints later in the file.
- 2026-10-04: frontend/lib/api-types.ts is generated by `npm run gen:api` and committed. Reason: Vercel's build and the judges' `docker compose up` have no running backend to generate it from.
- 2026-10-04: shadcn/ui uses its current default style (base-nova, built on Base UI, not Radix); components are added only through the shadcn CLI. Reason: it is what the CLI installs now, and mixing Radix-based examples would break the components.
- 2026-10-04: Upload limit is 30 MB, not 50. Reason: Cloud Run rejects request bodies over 32 MiB; 30 MB leaves room for multipart overhead.
- 2026-10-04: Search queries are embedded with BGE's query instruction ("Represent this sentence for searching relevant passages: "), passages without it; chunk sizes are counted with the model's own tokenizer. Reason: that's how bge-small-en-v1.5 is meant to be used for retrieval, and real token counts keep every chunk under the 512-token limit.
- 2026-10-04: In checkpoint 1, a failed upload keeps its original file in Storage, deletes its partly written chunks, and still returns 202 with status "failed" and a short error. Reason: no half-indexed sources in retrieval, and S4's jobs can retry from the stored file.
- 2026-10-04: python-multipart added to the backend and to stack.md's Web framework row. Reason: FastAPI needs it to parse multipart file uploads.
